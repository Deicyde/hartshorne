# Sheaf Hom as a left-exact functor

## Prior implementation guidance

For a ringed space `(X,O_X)` and an `O_X`-module `F`, package
`𝓗om_X(F,-)` as an additive endofunctor of `X.Modules` and prove that it is
left exact. Its global sections identify naturally with global module
morphisms from `F`.

The unique main result is left exactness of the endofunctor; the functorial
packaging and global-sections identification are supporting API.

## Ringed-space generalization plan

The article is stated for a ringed space, so its Lean uses the general sheaf Hom
`Hartshorne.Ringed.moduleSheafHom` from stage 1, not the scheme `Hartshorne.moduleSheafHom`.
Setting: `{X : TopCat.{u}} {R : Sheaf (Opens.grothendieckTopology X) CommRingCat.{u}}`, modules `SheafOfModules.{u} (ringCatSheafOf R)`, new general declarations in namespace `Hartshorne.Ringed` under `src/Hartshorne/RingedSpace/`. Schemes are the case `R := X.sheaf`, for which `SheafOfModules (ringCatSheafOf X.sheaf)` is definitionally `X.Modules`. It becomes ready after stage 1 (`RingedSpace/ModuleSheafHom.lean`:
`Ringed.moduleSheafHom`, `Ringed.moduleSheafHomMap`,
`Ringed.moduleSheafHomGlobalSectionsLinearEquiv`, `Ringed.moduleSheafHomData`). Package
`Ringed.moduleSheafHomFunctor F : SheafOfModules (ringCatSheafOf R) ⥤ SheafOfModules (ringCatSheafOf R)`
from `Ringed.moduleSheafHomMap`, prove it additive and left exact (stalkwise or via
sections, using that sections over `U` are morphisms `F.over U ⟶ G.over U` and that
`Hom(F.over U, -)` preserves kernels), and identify its global sections with
`Ringed.moduleSheafHomGlobalSectionsLinearEquiv`. Downstream, sheaf-ext and
sheaf-ext-tensor-dual (III Prop. 6.7) build on this functor.

The full staged plan (setting, route, all stages, claim sets) is in the implementation note of the Modules and quasi-coherent sheaves container (`af_cef7a5b34bf9a0c78dc51155`).
